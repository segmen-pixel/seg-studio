# Seg-Studio はじめてのハンドブック

> **この文書の位置づけ**：サンプル画像を1セット使い、画像を取り込み、欠陥を塗り、学習させ、モデルをファイルに書き出して新しい画像を判定するまでを、順を追って体験するチュートリアルです。応用機能もこの流れの中で扱います。最短で結果を出したい場合は[はじめてのファーストラン手順](first-run-manual.md)を、機能ごとに調べたい場合は[ユーザーガイド](user-guide.md)を、インストール方法は[インストールの詳細](install.md)をご覧ください。

このハンドブックは、**Seg-Studio をまったく使ったことがない方**に向けたものです。プログラムを書く必要はありません。画像を入れる → 欠陥を塗る → 学習 → モデルを書き出す → 新しい画像を判定する、という一連の流れを、全16章で順に体験できます。

辞書のように引くのではなく、頭から順に読むように構成しています。1〜13章は、画面の操作だけで進められる基本の流れです。14章は、プログラムからモデルを呼び出したいエンジニア向けです。15〜16章は個数カウントを扱う追加の章で、必要な場合だけ読めば構いません（16章もエンジニア向けです）。

文中の専門用語は、巻末の[用語集](#用語集)で説明しています。

各章の目安は次のとおりです。

- **⏱ 所要時間**：1章あたり3〜15分
- **📸 スクリーンショット**：現在7枚（残りの撮影リストは `contributing/screenshots.ja.md`）
- **🎯 ゴール**：動くモデルと、それを呼び出す Python クライアントができあがること（Python の部分は任意。14章）

> 💡 説明には、`外観検査デモ` プロジェクト（キズと打痕の2種類の欠陥を探す）を例として使います。自分の画像でも、手順は同じです。

## 1. ようこそ

Seg-Studio は、**画像の中の欠陥を画素（ピクセル）単位で見つけられるように、コンピューターに教えるためのソフト**です（この処理を「セグメンテーション」と呼びます）。画像を集め、欠陥を塗り、学習させ、出来を確かめ、ファイル（ONNX / CoreML）に書き出してほかの環境で使うところまでを、1つの画面で行えます。使うのに Python は必要ありません。

### こんな人におすすめ

- 目視検査を AI に置き換えたい方
- コードを書くより、画面の操作で進めたい方
- 業務で使える結果が必要なチーム

### できること

- Web ブラウザだけで完結
- クリック1回で欠陥を囲む（SAM）
- 欠陥を切り貼りして新しい画像を作る（Perlin CutPaste）
- 屋外向けに、日中・夕方・夜の色合いに変える（Lighting）
- iPhone / iPad 上で学習を続けられるモデルを書き出す（CoreML Updatable）
- 日本語の画面（英語にも切り替え可能）

![Seg-Studio のタブ全体像](assets/handbook/01_overview.png)

> **ポイント**：タブは、作業する順に左から右へ並んでいます。迷ったら、1つ左のタブに戻ってください。

## 2. アプリを起動して画面を知る

### 起動のしかた

[インストールの詳細](install.md)の手順でインストールした場合、Windows では Seg-Studio のフォルダにある `start-windows.bat` をダブルクリックします。macOS では `bash start-macos.sh` を実行します。準備ができると、Web ブラウザで `http://localhost:8002/ui/` が自動的に開きます。

<details><summary>詳しく：そのほかの起動スクリプトと再起動（エンジニア向け）</summary>

`scripts/` 以下の起動スクリプトでも起動できます。

```bash
# Windows
scripts\windows\start_local_windows.bat

# macOS
bash scripts/macos/start_local_macos.sh
```

API の起動が完了すると、ブラウザで `http://localhost:8002/ui/` が自動的に開きます。

Windows では、`restart-windows.bat` でトレーナー API だけを再起動できます。設定画面で「次回サーバー起動時に反映されます」と表示される変更は、この再起動で反映されます。LAN トークンを再利用するので、ブラウザのセッションは切れません。新しいサーバーは切り離して起動するので、SSH 経由で再起動した場合も、SSH のセッションを終えたあともサーバーは動き続けます。学習の実行中やキュー待ちのときは、`--force` を付けない限り再起動を拒否します。

</details>

### 画面のタブ構成

| タブ | 何をするところか |
|---|---|
| **プロジェクト** | プロジェクトの一覧表示、作成、切り替え |
| **ラベル** | 画像の欠陥を塗る |
| **学習** | 学習の設定と実行 |
| **結果タブ** | 学習が終わった Run（学習1回分）ごとに、**結果を開く**を押すと開く。スコア、ヒートマップ、領域数（CCA）、ライブ検査の表示がある |
| **ライブ検査** | カメラをつないで、その場で判定する |

> **ポイント**：右上の⚙️アイコンから設定メニューを開けます。ほとんどの項目は既定値のままで構いません。

## 3. プロジェクトを作る

「プロジェクト」は、1つの検査の仕事で使う画像、塗った欠陥、学習結果をひとまとめにした作業フォルダです。

### 手順

1. **プロジェクト**タブを開く
2. プロジェクト名の欄に名前を入れる（例：`新しい検査ライン`）
3. **プロジェクト作成**をクリック

![プロジェクト作成フォーム](assets/handbook/03_create_project.png)

### 保存のされかた

- ID（短い識別番号）が自動で振られ、内部では `projects/{id}/` に保存されます。
- **名前はあとから変更できます**。ID は変わりません。

> **落とし穴**：同じ名前のプロジェクトを作っても、ID が違うので別のプロジェクトとして扱われます。切り替えるときは一覧から選んでください。

## 4. 画像を取り込む

### 方法 A：ドラッグ&ドロップ（おすすめ）

- **ラベル**タブを開き、左の画像リストにフォルダごとドラッグ&ドロップ
- 1枚から数千枚まで対応
- 画像は、ファイルの大きさに応じたまとまりで自動で送られる

<details><summary>詳しく：アップロードのまとめ方</summary>

1回に送る枚数（バッチサイズ）は各ファイルのバイト数から自動で決まるので、設定を変える必要はありません。Places365 のような 256px の画像なら**1リクエストあたり100枚**、4K の写真なら**1リクエストあたり5枚**ずつ送られます。

</details>

### 方法 B：動画から静止画を取り出す

- 動画ファイル（mp4 など）をドラッグ&ドロップ
- 「何フレームごとに1枚抽出しますか？」と聞かれたら、何コマごとに1枚取り出すかを指定
- 動画を自動で読み込んで画像に変換

### 方法 C：ZIP インポート

以前書き出したプロジェクトを丸ごと復元したいときに使います。

## 5. 見つけたいものを決める

モデルに何を見つけさせたいかを決めます。欠陥の種類それぞれを**クラス**と呼びます。

### 例（「外観検査デモ」プロジェクト）

| ID | 名前 |
|---:|---|
| 0 | 背景 |
| 1 | キズ |
| 2 | 打痕 |

![クラス設定パネル](assets/handbook/05_classes.png)

### ポイント

- **ID 0 は必ず背景**（欠陥以外のすべて）です。変更しないでください。
- クラスが多すぎると、塗る作業が一気に増えます。**実用的なのは3〜5クラス**です。
- 似たような欠陥はまとめて構いません。細かく分けすぎて学習が割れるよりは、まとめたほうが良い結果になります。

## 6. 欠陥を塗る

画像の欠陥を塗る作業を**アノテーション**と呼びます。塗った範囲は**マスク**（画素ごとにどのクラスかを記録した、目に見えない層）として保存されます。

### 6-a. ブラシの基本

![ブラシで塗っている場面](assets/handbook/06a_brush.png)

- **ブラシ**（`B`）：マウスをドラッグして塗ります。`[` `]` でサイズを変えられます。
- **消しゴム**（`E`）：なぞった部分を消します。

### 6-b. クリック1回で囲む SAM（目玉機能）

Meta 社の SAM（Segment Anything）モデルを内蔵しています。**クリック1回で欠陥を囲めます**。

#### 使い方

1. ツール列で **SAM** ツール（`S`。中心に点のある破線の円のアイコン）を選びます。
2. 欠陥を**クリック**します。クリックはすべて、対象を指定する点として扱われます。取りこぼした部分は、追加でクリックしてください。
3. 輪郭が粗すぎたり細かすぎたりする場合は、細かさ（**subpart** / **part** / **whole**）を切り替えます。
4. プレビューの内側をクリックするか、Enter を押して確定します。

#### ここが便利

- 読み込みに10秒ほどかかるのは初回だけで、それ以降はクリックするとすぐに反応します。
- 細かい輪郭まで自動で取れるので、ブラシで塗るより10倍ほど速く作業できます。

### 6-c. ひび割れ検出 / スポット検出

- **ひび割れ検出**（`C`）：ひび割れのような線状の欠陥に向いています。クリックすると候補が自動でなぞられるので、クリックで選んで Enter で確定します。
- **スポット検出**（`D`）：塗った見本に似た、点のような小さい欠陥を探します。見本を塗って**検出**を押し、**しきい値**（1〜60。大きいほど見つかる数が少ない）を調整してから、Enter で確定します。

<details><summary>詳しく：スポット検出のしくみ</summary>

LoG（Laplacian of Gaussian）によるブロブ検出を使っています。

</details>

### 6-d. 保存と元に戻す

- `Ctrl + Z` / `Ctrl + Y` で元に戻す / やり直し
- タブを切り替えたり、別の画像に移ったりすると自動で保存
- すぐに保存したいときは `Ctrl + S`

### 6-e. AI サポートパネル（任意）

ツール列の下端にある **AI** ボタンを押すと、**AI サポート**パネルが開きます。画像を読み取れる AI モデル（視覚モデル）がプロジェクトにラベルを付けていき、その様子を画面で確認できます。Seg-Studio を動かしている PC で、モデルサーバーが動いている必要があります。何も設定していなければ、パネルはその PC の Ollama を探します。

1. 先に何枚かは、自分でラベルを付けておきます。AI はそれを手本にします。また、残りの画像に取りかかる前に、そのうち最大3枚で試して、どの倍率で見るかを決めます。
2. 何をラベル付けするかを入力して、**実行**を押します。
3. 始める前に一度だけ、かかる時間の見込みとともに、進めてよいかを聞かれます。質問の下のボタン（**進める** / **やめる**）を押すか、同じ入力欄に答えを書いて**回答**を押してください。20分たっても答えが無い場合は、何もラベル付けせずに終了します。
4. 会話と、更新されていく画像を見守ります。**一時停止**、**再開**、**停止**は、いずれもステップの区切りで効くので、書きかけのまま残ることはありません。

実行の対象は、開始したプロジェクトだけです。人が描いたマスクや、人が OK を付けた画像は置き換えません。モデルが見る画像は、指示、プロジェクト名、ツールの結果とともに、パネルが使うモデルサーバーに送られます。

<details><summary>詳しく：接続のしくみと設定方法（エンジニア向け）</summary>

パネルでは、ツール呼び出しに対応した視覚モデルが、MCP ブリッジを通してプロジェクトを操作します。パネルでのサーバーとモデルの選び方、別のマシンにあるサーバーの設定（環境変数 `SEG_VLM_*` または `projects/runtime_settings.json` の `vlm` ブロック）、各ボタンの説明は[ユーザーガイド](user-guide.md#ai-サポートパネル)にあります。MCP ブリッジや、手持ちの AI クライアントからの使い方は、[AI サポートと MCP ブリッジ](ai-support.md)をご覧ください。

</details>

## 7. 良品画像を教える

欠陥が写っていない普通の画像も、学習にはとても大事です。問題がない状態とはどういうものかを、モデルに教えるためです。そのためのボタンが **OK** です。

### OK の印とは

画像に**空のマスク**（全部が背景）を付けて、「ここは OK」とモデルに教える機能です。モデルは「この画像には欠陥が1つもない」と覚えます。

### 手順

1. 画像リストで OK の画像を複数選択する（Shift クリックで範囲選択）
2. 上部の **OK** ボタンをクリックする（`Shift+C` でも可）

![OK ボタン](assets/handbook/07_mark_clean.png)

### 屋外用途での使い方（実例）

屋外で手持ちのカメラを使う場合は、背景がさまざまなので、誤検出（欠陥でないものを欠陥と判定すること）が出やすくなります。対策として、**Places365 のような一般的な屋内外の風景画像**を入れて、すべてに OK を付けると、モデルは「こういう景色はすべて OK」と覚えます。

> **ポイント**：OK を付けた画像は、学習用画像全体の**30〜50%程度まで**にとどめるのが安全です。入れすぎると、本物の欠陥の見逃しが増えます（Recall が下がります）。

> **落とし穴**：OK を付けた画像には、画像リストで **✓OK** のバッジが付きます。付け間違えた場合は、**OK** の隣の**消去**か、バッジの × を押すと元に戻せます。

## 8. 練習用の画像を自動で増やす

手持ちの画像から学習用の画像を増やすことを**データ拡張**と呼びます。方法は2つあります。

### 8-a. 欠陥を切り貼りして増やす（Perlin CutPaste 合成）

塗り済みの画像から欠陥をランダムに切り出し、ランダムな模様（Perlin ノイズ）で形を少し**歪ませて**から、別の場所に貼り付けます。

#### 使い方

1. **ラベル**タブの**拡張**ボタンを押す
2. **Perlin CutPaste** にチェックを入れる
3. **対象クラス**を選ぶ（複数のクラスを対象にする場合は「全クラス（混合）」）
4. 作る枚数と、形をどれだけ歪ませるか（変形強度）を調整する
5. **生成**を押す（数秒で新しい合成画像が追加される）

### 8-b. 日中・夕方・夜の版を作る（照明バリエーション、屋外向け）

同じシーンを**日中・夕方・夜**の色合いに変換して、画像を増やします。塗った欠陥はそのまま残り、変わるのは色だけです。

#### 使い方

1. 拡張ダイアログで**照明バリエーション**（時間帯）にチェックを入れる
2. 日中・夕方・夜から、好きな組み合わせを選ぶ
3. Perlin CutPaste と同時に使える（1回で2種類の拡張）

> **ポイント**：屋外のデータは元の画像が少ないことが多いので、これだけで**学習に使う画像が3倍**になります。

## 9. 確認用の画像の取り分け

### 何が起きるか

学習の前に、画像は3つのグループに分けられます（Prepare Dataset）。

- **train**：モデルが学習に使う画像
- **val**（validation）：学習中の出来を確かめるために取っておく画像
- **test**：最後の確認のために取っておく画像

そのうえで、学習が読み込める形にファイルを整えます。

### 操作は不要です

ボタン操作は要りません。**学習開始**を押すと、分割が**自動で実行されます**。Run 一覧には「データセットを準備中…」、続いて「データセットの準備完了（train=…、val=…）」と経過が表示されます。

分割の比率（既定値は val 15%、test 10%）を変えたい場合は、右上の **⚙️ 設定**で**検証比率** / **テスト比率**を調整してください。

### 欠陥あり画像と良品画像は別々に分けます（重要）

- **欠陥が写っている画像**と **OK 画像**は、**別々に分割**されます。
- そのため、val と test には両方が同じ比率で入ります。
- これにより、val が OK 画像だけで埋まり、スコア（F1）が0になる事故を防げます。

> **注意：よく似た写真が train と val の両方に入ることがあります**。この分割は、どの写真が同じグループに属するかを考慮しません。画像ファイル名から計算した値（SHA1）の順に並べて切り分けるだけなので、撮影セッション、ロット、ワークとは無関係な並びになります。そのため、同じワークの連写や、同じ部品を角度を変えて撮った画像が、train と val の両方に入ることがあります。**ほぼ同じ画像が train と val にまたがると、val のスコアは実力より良く出ます**。こうしたグループを含むデータでは、画像ごとの **train / test** の指定を自分で付けて、グループ全体を片側に寄せてください。指定した枚数は `report.json` に `manual_train_count` / `manual_test_count` として記録され、グループを考慮しない分割であることは `split_grouping: "none"` として記録されます。

<details><summary>詳しく：学習用コピーの保存形式（エンジニア向け）</summary>

#### 学習用コピーは PNG に再エンコードされます（RGB は可逆）

データセットの準備では、各画像の学習用コピーを `prepared/images/` に **PNG** で書き出します。これは単純なコピーではなく、再エンコードです。元の画像を開いて RGB に変換し、あらためて書き出すので、元のファイルとバイト単位で同一にはならず、アルファチャンネルは失われます。ただし、RGB の画素値そのものは変わりません。ここでいう「可逆」はこの意味です。その分、prepared フォルダは大きくなります。

もう1つ、知っておきたい点があります。`images/` にあるファイル自体が JPEG だった場合、その画素は準備の前からすでに劣化しています。取り込み時のエンコーダが導入される前の環境では、ファイル名にかかわらず、そうしたファイルが混ざっています。`GET /api/v1/projects/{id}/layout/doctor` は、ファイル名ではなく中身を調べて、実際にどんな画像が入っているかを報告します。

**容量とデコード速度を優先する場合**：JPEG 品質 95 は、オプトインで使えます。prepared フォルダがディスクに収まらない場合や、画像のデコードが GPU の足を引っ張っている場合にだけ、次のように設定します。

```
SEG_PREPARED_IMAGE_FORMAT=jpeg
```

設定したら、データセットの準備をやり直してください。

> **非推奨**：この環境変数が効くのは `prepared/images/` の学習用コピーだけで、そのコピー自体がいずれ廃止されます。代わりに、保存形式をプロジェクト単位で設定してください（`PUT /api/v1/projects/{id}/image-store`。新規プロジェクトの既定値は `PUT /api/v1/system/import-defaults`）。この設定は、すべての取り込み経路が `images/` に何を書き込むかを決めます。画素が最終的に置かれるのは `images/` のほうです。

どちらの設定でも、**4:4:4**（色差の間引きなし）の q95 JPEG で書き出されます。大きな写真では PNG の数分の1の大きさになりますが、以前の既定だった 4:2:0 よりはバイト数が増えます。

**JPEG を選んだときの代償**：品質 95 で加わる量子化ノイズは、欠陥の内側にも外側にも一様に広がるもので、欠陥だけを選んで潰すものではありません。ただし、**1〜2画素幅の欠陥や、コントラストが極めて低い欠陥**が対象の場合は、信号対量子化比が大幅に悪化します。しかも、**その悪化はスコアには現れません**。学習も評価も再エンコード後のコピーを読み、推論だけが元のファイルを読むためです。色差だけの欠陥が弱まらないのは、4:4:4 で書き出しているためです。libjpeg の既定の 4:2:0 では、1画素幅の色の線のコントラストが **16.25 → 5.21** まで落ちます（4:4:4 なら 16.25 → 16.21）。

実際に使われた形式は、`prepared/report.json` の `prepared_image_format` に記録されます。

</details>

## 10. 学習の設定を決める

### まず、どんな仕事かを選ぶ

**学習**タブには、2つのモードカードがあります。**欠陥検知**（マスクを塗って学習し、欠陥を見つける）と、**個数検査**（すでに塗ったマスクから物体の個数を数える。15章で説明）です。**モードを選ぶまで「学習開始」ボタンは押せません**。この通しの例では、**欠陥検知**を選びます。

### おすすめ値をそのまま使う（Auto-config）

画像の枚数や欠陥の大きさなどから、モデルの種類（`arch`）、学習に使う画像の切り出しサイズ（`patch_size`）、モデルの幅（`base_channels`）を推定して表示します。**迷ったら、この値のままで構いません**。

### 手動で設定する（慣れてきたら）

| 項目 | 意味 | 目安 |
|---|---|---|
| arch | モデルの種類 | simpleunet（既定値。小さく高速）/ stdc（精度が上がることが多く、判定が最も速い） |
| patch_size | 学習のときに画像から切り出す正方形の大きさ | 256（既定値。変える必要はほとんどない） |
| output_stride | 輪郭をどれだけ細かく描くか | 2 または 4（細かい輪郭なら 2） |
| epochs | 学習用画像全体を何周するか | 80（既定値）。伸びなくなったら自動で止まり（early stopping）、この回数に達してもまだ改善していれば自動で延びる |

## 11. 学習させる

### 手元のパソコンで

- **学習開始**ボタンを押すと、学習が始まります。NVIDIA のグラフィックボード（CUDA）があればそれを使い、無ければ Apple のグラフィックチップ（MPS）を使います。どちらも無い場合は CPU（パソコンの主な処理装置）を使いますが、大幅に遅くなります。個数検査（15章）の学習だけは、NVIDIA のグラフィックボード（CUDA）が必要です。
- 学習の進み具合は、**モデル一覧**にエポックとそこまでの最高 F1（スコア。高いほど良い）が、**ログ**パネルにエポックごとの loss（学習が進むほど下がる値）が表示されます。
- 1周（epoch）ごとに、モデルの途中経過（チェックポイント）が自動で保存されます。

## 12. 結果をじっくり見る

### スコア

- **F1**：最も重要な、0〜1 のスコアです。「欠陥を見逃さない」ことと「欠陥でないものを欠陥と言わない」ことのバランスを表します。同じデータセットで学習した Run どうしで比較してください。どのデータにも通用する合格ラインはありません。
- **mIoU**：モデルが描いた輪郭が、自分で塗った輪郭とどれだけ重なるかを表します。F1 が高いのに mIoU が低い場合は、輪郭が甘い可能性があります。
- **Precision / Recall**：どちらの方向に間違えているかを判断する材料です。Precision が低ければ誤検出（FP）が多く、Recall が低ければ見逃し（FN）が多いということです。

### 結果の見方

| 機能 | 使いどき |
|---|---|
| **ヒートマップ** | モデルの自信の度合いを色で表示する。どこに自信があり、どこが怪しいかがわかる |
| **CCA（連結成分分析）** | 見つかった領域がいくつあり、それぞれどのくらいの大きさかを調べる |
| **Pattern overlay** | 欠陥だけを元の画像に重ねて見る |
| **ライブ検査** | カメラ映像をその場で判定する |

### しきい値の調整

右側のスライダーで**推論時の confidence しきい値**（どれだけ自信があれば欠陥と判定するか）を変えると、誤検出と見逃しのトレードオフがすぐにわかります。

## 13. モデルをファイルに書き出す

学習したモデルを、ほかのソフトで使えるファイルとして保存することを**エクスポート**と呼びます。どの形式が必要かは、モデルをどこで動かすかで決まります。そのシステムをほかの人が作っている場合は、その人に確認してください。

### エクスポート形式

| 形式 | 用途 |
|---|---|
| **ONNX** | 多くの環境で使える形式。サーバーでの判定や、Python / C++ のプログラムから使う |
| **CoreML** | iPhone / iPad / Mac のアプリに組み込む |
| **CoreML Updatable** | **iPhone / iPad（iOS）上で再学習**できる特殊な形式 |
| **OpenVINO** (FP32/FP16/INT8) | 現場に置く小型機器などで、Intel の CPU、内蔵 GPU（iGPU）、AI チップ（NPU）を使って判定する |

![エクスポートメニュー](assets/handbook/13_export.png)

### 手順

1. **学習**タブで学習済みの Run を選び、**結果を開く**で結果タブを開く
2. **学習モデルを出力**をクリックし、ONNX / CoreML / CoreML (Updatable) から形式を選んで実行する
3. ダウンロードリンクから `.onnx` / `.mlmodel` を取得する

> **OpenVINO だけは手順が別です**：**学習**タブの Run にある OpenVINO メニューから、FP32 / FP16 / INT8 を選びます。

> **ポイント**：CoreML Updatable では、モデルの最後の層（最終 Conv レイヤ）だけを iOS 側で再学習できます。そのため、現場でユーザーごとに微調整するアプリに便利です。

## 15. 個数を数える

画像の中のねじ、部品、錠剤が**何個あるか**を、触れ合ったり重なったりしている場合も含めて知りたいときは、個数カウントのモード（インスタンスモード）を使います。**すでに塗ってあるマスクから**カウント用のモデルを学習するので、**1個ずつ印を付ける作業はまったく要りません**。

### しくみ

塗ったマスクを物体1個ずつの切り抜きに分け、それをコピー&ペーストして練習用の画像を作ります。こうして作った画像では、どの物体がどこにあるかという正解が、1個ずつ正確にわかっています。**端と端で接触したペア**（同軸で接触したペア）も含めます。カウントモデルがよく間違えるケースだからです。

確認用（検証用）には、**練習用画像の合成に一度も使っていない元の画像**を必ず使います。数えるときのしきい値は、学習のあとで、**実際に書き出されるモデル**に対して調整します。

**アクティブなクラスはすべてカウントされます**。対象を1つ選ぶ必要はありません。モデルが全クラスを学習し、クラスごとの個数を返します。

<details><summary>詳しく：使っているモデル</summary>

カウントモデルは RF-DETR-Seg です。セマンティックマスク（6章で塗った通常のマスク）から、コピー&ペーストによる合成で物体1個ずつの正確な正解を作り、それを使って学習します。

</details>

### 手順

1. いつもどおりマスクを塗ります（6章）。対象のクラスが写った画像は**4枚**が下限で、多いほど良い結果になります。足りているかどうかは、下にあるプレビューで確認できます。
2. **学習**タブで、**個数検査**のモードカードを選びます。
3. 練習用画像の作り方を変えたい場合は、学習タブの**詳細設定**を開きます（9章で使った、右上の ⚙️ 設定ウィンドウではありません）。1枚あたりの物体数、接触したペアの出やすさ（スタックペア率）、1個あたりの大きさの範囲（単体面積帯。`0` なら自動）を変えられます。プレビューの**生成**を押すと、合成された画像を数枚確認できます。
4. 学習を開始します。既定は **Small** です。**Medium** にすると精度がはっきり上がり、3つ目のサイズとして **Large** も選べます。グラフィックボードのメモリ（VRAM）が少ない環境で自動調整されるのは、Small と Medium だけです（バッチを半分にして gradient accumulation を2倍にし、実効バッチを保ちます）。Small の下限は約 3.5 GB です。**Large はメモリの実測値が無いため、自動調整の対象外**です。指定したバッチのまま実行されるので、メモリ不足（OOM）になることがあります。その場合は、手動でバッチを下げてください。

   | サイズ | batch 8 | batch 4 | batch 2 |
   |--------|---------|---------|---------|
   | Small | 8.0 GB | 5.5 GB | 3.5 GB |
   | Medium | 16.0 GB | 9.5 GB | 6.0 GB |

5. **結果**タブで画像を判定します。画像上の物体に1個ずつ番号が付き、ヘッダーにクラス別の個数が表示されます。**検出ハイライト**に切り替えると背景が暗くなり、物体ごとに色が変わるので、**接触した2個が1個として数えられていないか**を最も速く確認できます。
6. **学習モデルを出力** → **ONNX (Serving)** でモデルを登録します。有効化すると、serving API の `POST /count` が画像ごとの個数を返します（16章）。

### 大きい画像は自動でタイルに分けて処理されます

**この機能に設定は要りません**。大きい写真は 768×768 の小片（タイル）に分けて処理されるので、小さい物体が縮小されて消えることはありません。768 より小さい画像は1枚のまま扱われ、タイル分割が無かった頃と同じ動作になります。

<details><summary>詳しく：タイルに分ける理由とサイズの変え方（エンジニア向け）</summary>

検出器の入力サイズは固定なので、写真全体を渡すと縮小されます。たとえば、**2560px のフレームにある 110px のねじは、16px ほどになって検出器に届きます**。これでは、ほとんど情報が残りません。

そこで学習では、**撮影時の解像度のまま 768×768 のパッチ**を合成します。推論でも同じ 768 のパッチで画像を走査し、検出結果をつなぎ合わせます。

物体に比べてパッチが小さいほど、継ぎ目で切れる物体が増え、そこで数を取りこぼします。また、大きなタイルを少なく使うほうが、処理も速くなります。既定値が 768 なのはそのためです。

768 より小さい画像はパディングして1パッチとして扱うので、タイル分割が無かった頃と同じ動作になります。512px の写真のプロジェクトはこれまでどおりで、タイル分割されるのは大きいフレームだけです。

変更したい場合は、`instance_patch_size` に画素サイズ（0〜4096）か `0`（タイル分割オフ）を指定できます。既定の 768 は、Small の入力 384 の2倍です。選んだ値は、書き出す契約に記録されます。**学習と推論では必ず同じパッチサイズを使う必要がある**からです。食い違ってもエラーにはならず、個数だけが狂います。

</details>

### 得意・不得意

- **ばらばらに置かれた硬い部品に最も向いています**（ねじ、ピン、プレス部品）。大きく変形するものや、密に積み重なったものは、実際に塗った画像がもっと必要になることがあります。プレビューを確認し、合成された画像が実際のシーンと似ていなければ、面積帯を調整するか、塗る画像を増やしてください。
- **1回の処理で報告できる物体の数には上限があります**（全クラスの合計）。タイル分割なしのモデルでは、個数が上限の90%を超えると、自信のある数字の代わりに**取りこぼし警告**が付きます。その場合は、画像を分割するか、切り出す範囲を狭めてください。既定のタイル分割では、タイルごとに上限があります。
- **タイルの重なり幅より大きい物体**は、継ぎ目にまたがることがあります。既定の 768 のタイルでは重なり幅が 192px なので、それより小さい物体なら問題ありません。大きい物体には、より大きいタイルが必要です。

<details><summary>詳しく：クエリ数の上限（エンジニア向け）</summary>

この上限は**モデルのクエリ数**で、1回の推論で出力できる検出数の上限です（全クラス共通）。値は書き出したモデルが持っているもので、200 に固定されているわけではありません。これが画像1枚全体の上限になるのは、タイル分割をオフにしたとき（`instance_patch_size` が 0）だけです。既定のタイル分割では、タイルごとに上限があります。タイル分割なしのモデルでは、上限の90%を超えると、自信のある数字を返す代わりに取りこぼし警告が付きます。

</details>

## 16. エンジニア向け：別のプログラムで個数を受け取る

> **この章は、カウントモデルを自分のプログラムにつなぐ方向けです**。画面だけで使う場合は、読み飛ばして構いません。

serving レジストリでカウントモデルを有効化すると、`POST /count` が画像を1枚受け取って結果を返します。CPU で動作し、GPU は必要ありません。

```bash
curl -F "image=@tray.png" http://localhost:8001/count
```

```json
{
  "model_id": "b42d4695-...",
  "count": 40,
  "counts_by_class": {"1": 38, "2": 2},
  "class_names": {"1": "screw", "2": "washer"},
  "threshold": 0.3,
  "dedup_iou": 0.7,
  "image_size": [2560, 2048],
  "inference_time_sec": 0.52,
  "instances": [
    {
      "id": 1,
      "class_id": 1,
      "class_name": "screw",
      "conf": 0.9812,
      "bbox": [412, 233, 118, 121],
      "centroid": [470.4, 293.1],
      "area": 8842,
      "rle": {"size": [2048, 2560], "counts": []}
    }
  ]
}
```

| フィールド | 意味 |
|---|---|
| `count` | 全クラス合計の個数 |
| `counts_by_class` | クラス別の個数（キーはプロジェクトのクラス ID） |
| `bbox` | 元の画像の画素座標で表した `[x, y, 幅, 高さ]` |
| `centroid` | マスクの**面積重心**（1次モーメント）。箱の中心ではありません。ピッキング用途にはこちらを使ってください |
| `area` | マスクの画素数 |
| `rle` | COCO の非圧縮 RLE（列優先）。学習側が書き出すものと同じ形式 |
| `threshold` / `dedup_iou` | モデルの校正に使った値。呼び出し側で記録できるように返しています |

### 個数が足りない可能性があるとき

検出器が1回の推論で出せる検出数は、そのモデルが持つクエリ数が上限です（全クラス共通）。この値は 200 に固定されているわけではなく、serving は有効化したモデルのエクスポートからその値を読み取って返します。上限に近づくと、レスポンスに次の項目が追加されます。

```json
"truncation_warning": "191 instances is close to this model's per-image limit of 200; the real count may be higher",
"max_instances_per_image": 200
```

これは「191個」ではなく「**191個以上**」として扱ってください。フレームを分割するか、切り出す範囲を狭めてください。

**この警告が付くのは、タイル分割なしのモデルだけです**。パッチで学習したモデル（`instance_patch_size` の既定値が 768 なので、通常はこちら）は画像をタイルに分割し、タイルごとにクエリの上限を持ちます。そのため、画像1枚あたりの上限という考え方が無くなり、上記のキーは返りません。ここで説明した動作が必要な場合は、学習時に `instance_patch_size` を 0 にしてください。

### しきい値が校正されていないとき

確信度のしきい値は、学習時に、アノテーション済みの検証用（validation）画像を候補値ごとに数えて決めます。そのため、検証用の側にアノテーション済みの画像が最低1枚必要です。無い場合は既定値のまま出荷され、レスポンスにその旨が表示されます。

```json
"threshold_warning": "threshold 0.3 was not calibrated: the training run had no annotated validation image to measure against, so this is the default. Counts may be systematically high or low."
```

よくある原因は、アノテーション済みの画像すべてに、単体面積帯から外れた領域が含まれていたことです。物体を1個ずつ別の領域として塗った画像を1枚追加して、学習し直してください。

### エラー

| ステータス | 意味 |
|---|---|
| 503 | モデルが有効化されていない |
| 409 | 有効なモデルがセマンティックセグメンテーション用。`/segment` を使ってください |

## おつかれさまでした 🎉

ここまでで、元の画像から始めて、ほかのプログラムから呼び出せる動くモデルまでを一通り作りました。

### 次のステップ

- ✅ 自分の業務の画像で、同じ流れを1回通す
- ✅ [カタログ](catalog.md)で、ほかの便利な機能をひととおり眺める
- ✅ 誤検出が多い場合は、さまざまな良品画像を入れ、OK を付けた画像を増やしてみる
- ✅ 精度をさらに詰めたい場合は、おすすめ値（Auto-config）に頼らず手動で調整する

## 用語集

| 用語 | 意味 |
|---|---|
| **アノテーション** | 画像の欠陥を塗って、モデルに何を探すかを教える作業 |
| **マスク** | アノテーションを保存したもの。画素ごとにどのクラスかを記録した画像 |
| **クラス** | 見つけたいものの種類（例：キズ、打痕）。ID 0 は必ず背景 |
| **背景** | 画像の中で欠陥ではない部分すべて |
| **セグメンテーション** | 箱で囲むのではなく、画素1つ1つがどのクラスかを判定すること |
| **SAM** | Segment Anything Model。Meta 社のモデルで、クリックした物体の輪郭を自動で取る |
| **OK 画像** | 欠陥なしと印を付けた画像。空のマスクが付く |
| **データ拡張** | 手持ちの画像から学習用の画像を増やすこと |
| **Perlin CutPaste** | 塗った欠陥を切り出し、ランダムな模様（Perlin ノイズ）で形を歪ませて別の場所に貼るデータ拡張 |
| **照明バリエーション（Lighting）** | 画像を日中・夕方・夜の色合いに変えるデータ拡張 |
| **train / val / test** | 画像を分ける3つのグループ。学習に使う画像、学習中の確認用、最後の確認用 |
| **学習** | 塗った画像からモデルが覚えること |
| **モデル** | 学習の成果物。新しい画像の欠陥を見つける |
| **Run（ラン）** | 1回分の学習とその結果 |
| **epoch（エポック）** | 学習用画像全体を1周すること |
| **チェックポイント** | 学習の途中で保存したモデル |
| **early stopping** | スコアが伸びなくなったら、学習を自動で止めること |
| **パッチ / patch_size** | 大きな画像から切り出した正方形の小片と、その大きさ（画素） |
| **arch** | モデルの種類（例：simpleunet、stdc） |
| **Auto-config** | 画像を見て Seg-Studio が提案する設定値 |
| **loss** | 学習が進むほど下がる値。低いほど良い |
| **F1** | 見逃しと誤検出のバランスを表す、0〜1 の主要なスコア |
| **mIoU** | モデルが描いた輪郭と、塗った輪郭の重なり具合を表すスコア |
| **Precision / Recall** | Precision は、検出したもののうち本物の欠陥の割合。Recall は、本物の欠陥のうち見つけられた割合 |
| **FP / FN** | 誤検出（欠陥でないものを欠陥と判定）/ 見逃し |
| **confidence しきい値** | どれだけ自信があれば欠陥と判定するかの境目 |
| **ヒートマップ** | モデルの自信の度合いを色で表した図 |
| **CCA（連結成分分析）** | 見つかった領域の数と大きさを数えること |
| **推論** | 学習済みモデルで画像を判定すること |
| **エクスポート** | モデルを、ほかのソフトで使えるファイルに書き出すこと |
| **ONNX** | 多くの環境で使えるモデルのファイル形式 |
| **CoreML / CoreML Updatable** | Apple のモデル形式 / 端末上で学習を続けられる版 |
| **OpenVINO** | Intel のプロセッサでモデルを動かすための形式。FP32 / FP16 / INT8 は数値の精度の選択肢 |
| **GPU / CUDA / MPS / CPU** | グラフィックボード / NVIDIA の GPU のしくみ / Apple の GPU のしくみ / パソコンの主な処理装置 |
| **VRAM** | グラフィックボードのメモリ |
| **OOM** | メモリ不足。処理に必要なメモリが、ボードの容量を超えた状態 |
| **バッチ** | 1回の処理でまとめて扱う画像の枚数 |
| **インスタンスモード** | 物体を1個ずつ見分けて数える、個数カウントのモード |
| **重心（centroid）** | 見つかった領域の中心点 |
| **バウンディングボックス（bbox）** | 見つかった領域を囲む長方形 |
| **API** | ほかのプログラムが Seg-Studio とやり取りするための窓口 |
| **SDK** | プログラム（ここでは Python）から Seg-Studio を呼び出すための既製のライブラリ |
| **MCP ブリッジ** | AI アシスタントがプロジェクトを操作するときに使う接続口 |
