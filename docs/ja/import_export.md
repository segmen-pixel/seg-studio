# インポート / エクスポートのフォーマット仕様

Seg-Studio のプロジェクトデータを外部ツールとやり取りするための仕様です。

---

## エクスポート

### エンドポイント

```
GET /api/v1/projects/{project_id}/datasets/export
```

任意のクエリパラメータ `resize_scale`（0.1〜1.0）を指定すると、エクスポート時に画像（Lanczos）とマスク（最近傍）を縮小します。

プロジェクトタイルの**エクスポート**ボタンから実行します。エクスポートダイアログでは、元データのサイズ、任意で実行する前景（欠陥領域）の分析、「縮小して軽量化」オプションを確認してから ZIP をダウンロードできます。

### 出力形式

ZIP アーカイブです。ファイル名は `{プロジェクト名}_{YYYYMMDD_HHMM}.zip` です（縮小した場合は `{プロジェクト名}_s{scale}_{YYYYMMDD_HHMM}.zip`）。

```
{prefix}/
├── images/          # 元画像（オリジナルファイル名を保持）
│   ├── sample_001.png
│   ├── sample_002.jpg
│   └── ...
├── masks/           # アノテーションマスク（グレースケール PNG）
│   ├── {item_id}.png  # 未アノテーション画像には全ゼロ（背景のみ）マスクが入る
│   └── ...
├── train.txt        # 学習用 item ID リスト（1行1ID）
├── val.txt          # 検証用 item ID リスト（1行1ID）
├── training/        # 学習ラン（チェックポイント・設定・メトリクス）
│   ├── runs/{run_id}/...   # インポートでは読み込まれない
│   └── pretrained/  # インポート済み事前学習チェックポイント（ある場合）
└── metadata.json    # プロジェクトメタデータと画像ごとのマーク
```

### masks/ のフォーマット

| 項目 | 値 |
|------|----|
| ファイル名 | `{item_id}.png` (item ID) |
| チャンネル | シングルチャンネル（グレースケール、PIL mode `"L"`） |
| ピクセル値 | クラス ID（0 = background、1+ = ユーザー定義クラス） |
| 無視インデックス | 255（旧バージョンの未塗り領域） |

> **255 は学習から除外されません。** 「無視インデックス」という名前ですが、マスク値 255 は旧バージョンで塗られなかった画素を表し、データセットの準備段階で背景（クラス 0）に変換されます。loss や metric に 255 のまま渡ることはないため、モデルはその画素を背景として学習し、スコアでも背景として数えられます。`ignore_index` フィールドは 255 に固定された契約値で、範囲外のクラス ID を内部で安全に丸めるために予約されています。本当に無視したい領域がある場合は、255 に頼らないでください。

PNG ではなくタイルで保存されている大きな画像のマスクも、ほかのマスクと同じ PNG として書き出します。その際は、タイルから数行ずつ帯状に読み出します。`resize_scale` による縮小も、ほかのマスクと同じく最近傍で行います。


### metadata.json

```json
{
  "project_id": "uuid-string",
  "project_name": "Bolt",
  "exported_at": "2026-04-01T12:00:00",
  "num_images": 97,
  "num_train": 78,
  "num_val": 19,
  "classes": [
    { "id": 0, "name": "background", "color": [0, 0, 0] },
    { "id": 1, "name": "キズ", "color": [242, 36, 36] }
  ],
  "ignore_index": 255,
  "items": [
    { "id": "sample_001", "filename": "sample_001.png", "name": "sample_001.jpg",
      "hasMask": true, "markedClean": false, "set": "train" },
    { "id": "sample_002", "filename": "sample_002.png", "name": "sample_002.png",
      "hasMask": true, "markedClean": true },
    { "id": "sample_003", "filename": "sample_003.png", "name": "sample_003.png",
      "hasMask": false, "markedClean": false,
      "draft": true, "draftRun": "review", "draftReason": "境界が不明瞭" }
  ]
}
```

`items` の各要素は1枚の画像を表します。`id` と `filename` は常に含まれます。それ以外のフィールドは、`masks/` の画素だけでは表せない「その画像について決めたこと」の記録で、インポート時に読み戻されます（[画像ごとのマーク](#画像ごとのマーク)を参照）。

| フィールド | 出力条件 | 意味 |
|-----------|---------|------|
| `id` | 常に | item ID。マスクは `masks/{id}.png` |
| `filename` | 常に | `images/` 内のファイル名 |
| `name` | 設定されているとき | 画像一覧に表示される名前。無い場合、インポート後はファイル名を表示 |
| `hasMask` | 常に | `false`：マスクの無い画像。`masks/` 内のファイルは、エクスポート時に書き出した全ゼロの穴埋め |
| `markedClean` | 常に | `true`：**OK** 指定済み（確認済みで、ラベルを付けるものが無い画像）。全ゼロのマスクは未ラベルではなく負例 |
| `set` | `train` / `test` のときのみ | 学習 / テストへの手動割り当て |
| `draft` | 付いているとき | `true`：**要確認**フラグ、または学習ランが下書きして、まだ誰も確認していないマスク |
| `draftRun` | `draft` と一緒に | **要確認**フラグなら `"review"`、それ以外は下書きしたラン |
| `draftReason` | `draft` と一緒に（理由があるとき） | フラグを付けた理由 |
| `by` | エージェントがマスクを保存したとき | 書き込んだエージェント。人が保存したマスクには付かない |
| `synthetic` | 合成サンプル | `true`：合成機能で生成された画像 |

以前のバージョンのエクスポートには、`id` と `filename` しかありません。

### train.txt / val.txt

- `prepared/splits/` に分割（split）があれば、それを使います。
- 無ければ、エクスポート対象のすべての item を 80/20 でランダムに分割します。
- 1行に item ID を1つずつ書きます。

## インポート

### エンドポイント

```
POST /api/v1/projects/{project_id}/datasets/annotate/import_zip
```

**プロジェクト**タブの**インポート**ボタンで **ZIP ファイル**を選択します。ZIP のファイル名で新しいプロジェクトが作成され、そこにアーカイブの内容がインポートされます。

### 対応する ZIP の構造

インポートで読み込むのは、アーカイブ内の1か所だけです。ZIP の直下か、直下に画像が無くフォルダが1つだけある場合（エクスポートした ZIP や、フォルダを圧縮した ZIP）はそのフォルダです。その場所で、次のように画像とマスクを探します。

- `images/` フォルダに画像があれば、それを取り込む画像とします。マスクは、その隣の `masks/` フォルダ内の `.png` です。
- 無ければ、その場所に直接置かれた画像を取り込みます。隣に `masks/` フォルダがあれば、そこからマスクを読み込みます。

対象になるのは `images/` と `masks/` の直下にあるファイルだけで、**それより深いフォルダにある画像は取り込みません**。たとえば、エクスポートの `training/` 配下にある学習ラン（ランの確信度グラフは PNG です）、`prepared/` のコピー、画像のサブフォルダなどが該当します。`__MACOSX/`、`._*`、`Thumbs.db`、`.DS_Store`、`desktop.ini` は無視します。この場所に画像が1枚も無い場合はインポートがエラーになり、エラーメッセージには読み飛ばした画像が1つ示されます。

トップフォルダの中にも画像が無く、フォルダが1つだけある場合は、さらにその中へ進みます（合わせて最大3階層まで）。エクスポートした ZIP を Windows の**すべて展開**で展開すると、同じ名前のフォルダの中に入った状態になり、そのフォルダをもう一度圧縮すると2階層になるためです（パターン D）。この方法で `images/`・`masks/` の中に進むことはなく、トップフォルダより下では `training/`・`runs/`・`prepared/` にも進みません。

#### パターン A：フラット構造

```
MyProject.zip
├── images/
│   ├── img_001.png
│   └── ...
├── masks/
│   ├── img_001.png
│   └── ...
└── classes.json
```

#### パターン B：トップフォルダが1つ（Seg-Studio のエクスポート）

```
sample_20260401_1200.zip
└── sample_20260401_1200/
    ├── images/
    ├── masks/
    ├── metadata.json
    ├── train.txt / val.txt
    └── training/        # 取り込まれない
```

#### パターン C：画像を入れたフォルダ

```
photos.zip
└── photos/              # または ZIP 直下に画像を直接
    ├── img_001.jpg
    ├── img_002.jpg
    └── masks/           # 任意
        └── img_001.png
```

#### パターン D：展開して圧縮し直したエクスポート

```
sample_20260401_1200.zip
└── sample_20260401_1200/          # すべて展開が作ったフォルダ
    └── sample_20260401_1200/      # エクスポート本来のフォルダ
        ├── images/
        ├── masks/
        └── metadata.json
```

> 以前のバージョンは `images/` と `masks/` を**任意の深さ**で探し、`masks/` 以外にある画像をすべて取り込んでいました。そのため、エクスポートを取り込むと、学習ランのグラフが余分な画像として入っていました。深いフォルダ（例：`datasets/prepared/images/`）を前提に作った ZIP は、`images/` と `masks/` を最上位に移してください。

### 画像ファイル（images/）

| 項目 | 値 |
|------|----|
| 対応拡張子 | `.jpg` `.jpeg` `.png` `.bmp` `.tif` `.tiff` `.webp` |
| 大文字小文字 | 区別しない |
| 補足 | PNG 以外の画像は、インポート時に PNG に変換されます |
| 向き | EXIF の向き情報がある写真（スマートフォンやカメラを縦に構えて撮った写真など）は、ビューアーで見たときの向きに回転して保存し、向き情報は残しません。マスクはこの向きの画像と照合するので、マスクも同じ向きで用意してください |

### マスクファイル（masks/）

| 項目 | 値 |
|------|----|
| 対応拡張子 | `.png` のみ |
| チャンネル | シングルチャンネル（グレースケール）を推奨。RGB の場合、インポート時は OpenCV で読んだ第1チャンネル（BGR 順のため青）がクラス ID として使われるので、曖昧さを避けるには1チャンネルのグレースケールを使ってください |
| ピクセル値 | クラス ID（0 = background、1+ = ユーザー定義クラス） |

### マスクと画像の対応ルール

ZIP 内に `metadata.json` がある場合（つまり Seg-Studio からエクスポートした ZIP の場合）は、その `items` 配列（元のファイル名 → item ID）で対応付けます。それ以外の場合は、**ファイル名のステム（拡張子を除いた部分）が一致する**ものどうしを対応付けます。

```
images/bolt_001.png  ←→  masks/bolt_001.png   (ステム: bolt_001)
images/sample.jpg    ←→  masks/sample.png     (ステム: sample)
```

対応するマスクが見つからない画像は、マスクなし（未アノテーション）としてインポートされます。

### 画像ごとのマーク

`metadata.json` の `items` に [metadata.json](#metadatajson) の表にあるフィールドがあれば、インポート時に元に戻します。

- `markedClean: true`：画像は再び **OK** になります。ただし、マスクが取り込まれていて、何も塗られていない場合に限ります（塗りのあるマスクに付いた OK は無視します）。
- `hasMask: false`：`masks/` 内の全ゼロの穴埋めマスクは捨て、画像は未ラベルのままにします。
- `set`、`name`、`draft` / `draftRun` / `draftReason`（**要確認**フラグ）、`synthetic`：そのまま元に戻します。`by` は、マスクも一緒に取り込まれたときだけ戻します。

これらのフィールドが無い場合（以前のバージョンのエクスポートや、ほかのツールで作った ZIP）は従来どおり、含まれているマスクはすべて保存済みとして扱い、全ゼロのマスクは **OK** ではなく未ラベルの画像になります。

### クラス定義ファイル

`images/` の隣（または ZIP の直下）にある `classes.json` を最優先で使います。無ければ `metadata.json` の `classes` 配列（エクスポートの場合は、エクスポートした時点のプロジェクトのクラス）を使います。どちらも無い場合に限り、アーカイブのより深い場所にある `classes.json`（学習ランが持っているコピーなど）を使います。

```json
{
  "version": 1,
  "ignore_index": 255,
  "classes": [
    { "id": 0, "name": "background", "color": [0, 0, 0], "active": true },
    { "id": 1, "name": "キズ",       "color": [242, 36, 36], "active": true }
  ]
}
```

- `color`：RGB の配列 `[R, G, B]`
- `version`、`ignore_index`、`active` の各フィールドは任意

### インポート処理フロー

```
1. ZIP 選択 → ZIP ファイル名でプロジェクト作成
2. アーカイブをスキャン: images/, masks/, classes.json, metadata.json（深いフォルダは読み飛ばす）
3. 画像を PNG に変換（並列処理）して登録
4. metadata.json の items またはステム名でマスクを照合し、画像ごとのマークを復元
5. クラス定義を登録（classes.json または metadata.json）
6. マスク内に未定義クラス ID があれば自動補完（reconcile）
7. プロジェクト一覧を更新
```

### レスポンス

```json
{ "status": "ok", "image_count": 5, "mask_count": 4, "clean_count": 2,
  "classes_imported": true, "reconciled_classes": 0,
  "passed_over": 2, "passed_over_sample": ["images/old/img_006.png", "img_007.png"] }
```

`passed_over` は、画像を読み込む場所の外にあって取り込まなかった画像の数で、`passed_over_sample` はそのうち最大5件のパスです。エクスポート自身の `training/` フォルダにある画像は数えません（学習ランのグラフは意図的に取り込まないため）。この数は、**プロジェクト**タブに表示されるインポート完了のメッセージ（画像一覧に ZIP をドロップした場合は、そちらのメッセージ）にも表示されます。

### 制約事項

- 画像を読み込む場所に画像が1枚も無い場合は、エラーになります。
- インポートで復元されるのはデータセット（画像・マスク・クラス定義・画像ごとのマーク）です。ZIP 内の学習ラン・モデル・学習 / 検証の分割ファイルは取り込まれません。
- マスクだけ（画像なし）のインポートはできません。
- クラス定義ファイルは任意です（無くてもインポートできます）。
- マスクは `.png` のみ対応しています（それ以外の形式は無視されます）。

## 外部ツール連携ガイド

### 他ツールから Seg-Studio へインポートする場合

次の構造で ZIP アーカイブを用意してください。

```
project_name.zip
├── images/    # 元画像
├── masks/     # クラスID のグレースケール PNG（ステム名を画像と一致させる）
└── classes.json  # クラス定義（任意）
```

### Seg-Studio から他ツールへエクスポートする場合

エクスポートした ZIP を展開すると、次のものが入っています。

- `images/`：元の画像です（ファイル名も元のまま）。
- `masks/`：グレースケールのマスクです（ファイル名は item ID）。
- `metadata.json`：`items` 配列で、item ID と元のファイル名の対応、画像ごとのマーク（OK・要確認・学習 / テスト）を確認できます。
- `train.txt` / `val.txt`：学習 / 検証の分割情報を取得できます。
- `training/`：学習ラン（チェックポイント・設定・メトリクス）です。データセットだけが必要な場合は無視してかまいません（インポートでは読み込まれません）。
