# トラブルシューティング

**このページの読み方。** 各項目は、画面に表示される症状から始まります。その下に、次の2種類の手順を載せています。

- **まず試すこと**：マウス操作だけでできる手順です（Seg-Studio の再起動、ほかのアプリを閉じる、ページの再読み込み、設定の変更など）。コマンドは使いません。
- **詳しく調べる（コマンドを使います）**：コマンドを入力する画面（Windows ではコマンドプロンプトまたは PowerShell、macOS ではターミナル）が必要な手順です。慣れていない場合は、Seg-Studio をセットアップした方に相談するか、このページの最後の[問題を報告する](#問題を報告する)に進んでください。

エラーメッセージは、Seg-Studio に表示されるとおりの文字列で載せています。画面に出た文字列で、このページを検索できます（Ctrl+F / Cmd+F）。

> **Seg-Studio の再起動**は、このあと何度も出てきます。Windows では、Seg-Studio のフォルダにある `stop-windows.bat` をダブルクリックしてから、`start-windows.bat` をダブルクリックします（`restart-windows.bat` でも再起動できますが、学習の実行中や予約中は再起動しません）。macOS では、起動したときと同じように、Seg-Studio のフォルダで `bash stop-macos.sh` を実行してから `bash start-macos.sh` を実行します。

## 起動しない / API 接続不可

**症状**：ブラウザに「Connecting to server...」または「サーバーに接続しています。しばらくお待ちください。」が表示されたまま変わりません。

読み込み画面は、通常5〜15秒ほどで消えます（PC によって異なります）。1分たっても変わらない場合は、Seg-Studio を起動し直してください。

**まず試すこと**

1. Seg-Studio を再起動し（このページ冒頭の枠を参照）、ブラウザのページを再読み込みします。
2. 最新のログファイルを確認します。Seg-Studio のフォルダから、メモ帳またはテキストエディットで開けます。
   - Windows：`logs\windows\trainer_<タイムスタンプ>.log`（起動するたびに1つ作られます。いちばん新しいものを開いてください）
   - macOS：`logs/macos/trainer.log`

**詳しく調べる（コマンドを使います）**

1. サービスの状態を確認します。
   - Windows：`scripts\windows\status_windows.bat`
   - macOS：`lsof -iTCP:8002 -sTCP:LISTEN`
2. ログファイルを確認します。
   - Windows：`logs\windows\trainer_<タイムスタンプ>.log`（起動するたびに1つ作られます。`scripts\windows\status_windows.bat` で最新のログの末尾を表示できます）
   - macOS：`logs/macos/trainer.log`
3. ポート 8002 がほかのプロセスに使われていないか確認します。
   ```bash
   # Windows
   netstat -ano | findstr :8002
   # macOS
   lsof -i :8002
   ```
4. Python の仮想環境が正しく有効化（activate）されているか確認します。

## ブラウザが真っ白

**症状**：`http://localhost:8002/ui/` を開いても、画面が真っ白です。

**まず試すこと**

1. ページを再読み込みします。
2. Seg-Studio のフォルダに `apps\trainer_ui\dist\` があるか確認します。これは、アプリの画面部分を組み立てた結果（ビルド結果）です。無い場合は、インストーラー（Windows では `install-windows.bat`）をもう一度実行してください。インストーラーの最後の手順で画面部分を組み立てます。終わったら Seg-Studio を起動し直します。

**詳しく調べる（コマンドを使います）**

1. `apps\trainer_ui\dist\` フォルダがあるかどうかで、UI がビルドされているかを確認します。
2. ビルドされていない場合は、次を実行します。
   ```bat
   cd apps\trainer_ui
   npm install
   npm run build
   ```
3. 開発サーバーを使っている場合は、`http://localhost:5173` を開きます。
4. macOS では、Node.js（`npm`）が入っていないと、インストーラーは画面部分の組み立てを飛ばします。Node.js が入っているか確認し（無ければ `brew install node` で入れます）、`bash install-macos.sh` をもう一度実行してから、Seg-Studio を起動し直します。

## 学習中に「メモリが足りない」エラーで止まる（OOM / Out of Memory）

**症状**：学習中に「メモリが足りない」というエラー（`CUDA out of memory`）が出て止まります。

**まず試すこと**（すべてアプリの画面で操作できます）

1. **パッチサイズを下げる**：パッチサイズは、AI が一度に学習する画像の切り出しの大きさです。学習タブの設定で小さくします（例：256 → 192 → 128）。
2. **モデルサイズを小さくする**：学習タブの設定で、コンパクトかスタンダードを選びます。バッチサイズ（一度にまとめて学習する切り出しの枚数）の設定はありません。バッチサイズは、空いている GPU メモリに合わせてアプリが自動で決めます。NVIDIA の GPU でそれでもメモリが足りなくなった学習は、メモリを抑えた設定で1回だけ自動でやり直されます。
3. **GPU を多く使うほかのアプリを終了する**：ブラウザの GPU アクセラレーションを無効にします。
4. **VRAM 4GB の GPU の場合**（グラフィックボードのメモリが 4GB）：low-VRAM モードが自動的に適用されます。それでも OOM になる場合は、パッチサイズを 128 にしてください。
5. **macOS（MPS）**：ユニファイドメモリを使うため、ほかのアプリのメモリ使用量も影響します。メモリが不足する場合は、パッチサイズを下げるか、不要なアプリを閉じてください。

**詳しく調べる（コマンドを使います）**

- Windows / Linux：環境変数 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` が設定されていることを確認します（既定で設定されています）。

## GPU があるのに「CPU」しか選べない（CUDA が認識されない / Windows・Linux）

**症状**：GPU があるのに、選択肢に CPU しか表示されません。

**まず試すこと**

1. NVIDIA のグラフィックドライバを最新版に更新します。
2. Windows では、`install-windows.bat` をダブルクリックしてもう一度実行します。NVIDIA ドライバが入っていれば、GPU（CUDA）版の PyTorch が自動で選ばれます。
3. 学習タブの**デバイス**欄で、デバイスを手動で選びます。

**詳しく調べる（コマンドを使います）**

1. `nvidia-smi` で、NVIDIA ドライバが最新か確認します。
2. CUDA に対応した PyTorch がインストールされているか確認します。
   ```bash
   python -c "import torch; print(torch.cuda.is_available())"
   ```
3. `False` と表示された場合は、CUDA 版の PyTorch をインストールし直します。
   ```bash
   # 通常は cu128 (Turing/RTX 20xx 以降、Blackwell 含む)。
   # Maxwell/Pascal/Volta の古い GPU のみ cu124
   pip install --force-reinstall --no-deps --index-url https://download.pytorch.org/whl/cu128 torch torchvision
   ```
   これは `install-windows.bat` が実行しているのと同じコマンドです。`--force-reinstall` を付けると、インストール済みの torch が入れ替わります（付けない `pip install` は、インストール済みの torch をそのまま残し、条件を満たしていると表示するだけです）。`--no-deps` を付けると、ほかのパッケージはインストール済みのまま残ります。Windows では、代わりに `install-windows.bat cuda`（古い GPU では `install-windows.bat cuda124`）を実行し直してもかまいません。

## Mac の GPU が使われない（MPS が認識されない / macOS）

**症状**：Apple Silicon の Mac なのに、MPS デバイス（Mac に内蔵された GPU）が選択肢に表示されません。

**まず試すこと**

1. macOS 12（Monterey）以降か確認します（アップルメニュー →「この Mac について」）。
2. Intel Mac では MPS は使えません（CPU のみ）。

**詳しく調べる（コマンドを使います）**

1. MPS に対応した PyTorch がインストールされているか確認します。
   ```bash
   python3 -c "import torch; print(torch.backends.mps.is_available())"
   ```
2. `False` と表示された場合は、PyTorch をインストールし直します。
   ```bash
   pip install --upgrade torch torchvision
   ```

## SAM アシストが動かない

**症状**：SAM のクリック / ボックスによるセグメンテーション（ラベルタブにある、AI が輪郭を選んでくれるツール）でエラーが出ます。

**まず試すこと**

1. Seg-Studio のフォルダにある `models\sam_checkpoints\` を開き、モデルファイル（`mobile_sam.pt`、`sam2.1_hiera_tiny.pt` など）があるか確認します。
2. モデルファイルは、Windows ではインストール時に、macOS と Linux では SAM ツールを初めて使ったときにダウンロードされます。無い場合は、インターネットにつないだ状態で SAM ツールをもう一度使ってください。Windows では、`install-windows.bat` をもう一度実行してダウンロードし直すこともできます。その場合は、終わったら Seg-Studio を再起動します。ファイルをダウンロードできないときは、SAM ツールがファイル名を添えて「SAM のモデルファイルをダウンロードできませんでした」（NSS-5011）と表示し、AI サポートの実行も同じメッセージを出して止まります。
3. `logs\trainer_errors.log` をメモ帳またはテキストエディットで開き、具体的なエラーを確認します。

**詳しく調べる（コマンドを使います）**

1. `models\sam_checkpoints\` にチェックポイントファイルがあるか確認します。
2. 必要なファイルは `mobile_sam.pt`、`sam2.1_hiera_tiny.pt` などです。
3. `/api/v1/sam/models` エンドポイントで `downloaded: true` になっているか確認します（`checkpoint_exists` は、ファイルが無くても自動でダウンロードできる場合は `true` になります）。
4. ログ（`logs\trainer_errors.log`）で具体的なエラーを確認します。

## モデルの書き出し（エクスポート）が失敗する

**症状**：CoreML / ONNX のエクスポート（学習したモデルを検査装置などで使うための書き出し）に失敗します。

**まず試すこと**

1. 選んだランにモデルが保存されているか確認します。エラーで終わったランや、モデルが1度も保存されないうちに止めたランは書き出せません。
2. **CoreML** の書き出しは、macOS で実行することをおすすめします。

**詳しく調べる（コマンドを使います）**

1. **CoreML**：`coremltools` がインストールされているか確認します（macOS を推奨）。
   ```bash
   pip install coremltools
   ```
2. **ONNX**：`onnx` と `onnxruntime` がインストールされているか確認します。

## カウント：学習が始まらない

**症状**：個数カウントの学習が、すぐに「instance mode needs at least 4 annotated images containing one of classes [...]」というエラーで失敗します。

このメッセージは、対象のクラスが実際に塗られている画像が4枚未満であることを示しています。

**まず試すこと**（すべてアプリの画面で操作できます）

1. **マスクの枚数ではなく、クラスが実際に塗られている画像の枚数を数えてください。** 全体が値 255 で塗られたマスクは「未塗り」の扱いで、前景ではないため1枚にも数えません。ラベルタブでいくつか開き、クラスの色が本当に付いているか確認してください。
2. **OK** を付けた画像は数に入りません。定義上、すべて背景だからです。
3. このチェックは GPU を使う処理より前に行われるため、数秒で失敗します。メッセージには探したクラスが表示されます。想定と違う場合は、クラスパネルでどのクラスが**アクティブ**になっているか確認してください。

## カウント：個数が合わない

**症状**：報告される個数が、いつも実際より少ない、または多くなります。

**まず試すこと**（アプリの画面で操作できます）

1. **まずオーバーレイを見てください。** 結果タブの**検出ハイライト**をオンにすると、背景が暗くなり、個体ごとに色が分かれます。接している2個が同じ色なら1個に統合されており、1個が2色に分かれていれば分割されています。
2. **少なめで、きりの良い数で頭打ちになる場合**：1枚の画像で数えられる上限（既定の Small モデルでは100個、Medium / Large では200個）に達している可能性があります。切り出す範囲を狭めるか、フレームを分割してください。

**詳しく調べる（設定と API の詳細）**

1. **いつも約2倍多い場合**：タイル（画像を重なりのある小片に分けて処理する単位）ごとに重複して数えられています。書き出した契約に `patch_size` があるか確認してください。タイル分割で学習したモデルをタイル分割なしで推論した場合（またはその逆）、**エラーを出さずに**個数だけが狂います。
2. **少なめで、きりの良い数で頭打ちになる場合**：モデルサイズごとに決まった、1枚あたりの検出数の上限（既定の Small モデルでは100個、Medium / Large では200個）に達している可能性があります。`/count` のレスポンスに `truncation_warning` が付くのは、タイル分割をオフ（`instance_patch_size = 0`）にして書き出したモデルだけで、既定の 768 のタイル分割では付きません。個数そのものから上限に達しているかを判断し、切り出す範囲を狭めるか、フレームを分割してください。
3. **数個だけ少ない場合**：タイルの重なり幅より大きい物体が、タイルの継ぎ目にまたがって落ちている可能性があります。既定の 768 のパッチでは、重なり幅は 192px です。部品がそれより大きい場合は、`instance_patch_size` を上げてください。
4. **しきい値（判定の基準になる確信度の値）を確認してください。** `/count` は、使ったしきい値を `threshold` として返します。この値は学習時に hold-out 画像で校正したものなので、シーンが大きく異なる場合は別の値のほうが適していることがあります。

## カウント：合成サンプルが実際と違う

**症状**：プレビューに表示される合成画像が、実際のシーンに似ていません。

**まず試すこと**（アプリの画面で操作できます）

1. **物体が大きすぎる / 小さすぎる場合**：単体面積帯（1個の物体として扱う大きさの範囲）を、`0`（自動）ではなく明示的に設定してください。自動の場合は blob（塗られたひとかたまり）から推定するため、小さなゴミや極端に大きい blob が混じると推定がずれます。
2. **切り抜きが少なすぎる場合**：合成ログには、`n_cutouts` と、面積帯で除外された blob の数が出ます。ほとんどが除外されている場合は、面積帯がデータに合っていません。
3. **背景が単調な場合**：背景プレートは、アノテーション済みの画像からしか作られません。シーンの別の場所を写した画像を、さらに数枚アノテーションしてください。

## カウント：`POST /count` が 409 を返す

**症状**：`active model is a semantic-segmentation export; use /segment` が返されます。

これは、配信用に有効になっているモデルの種類が違うという意味です。個数を数えるモデルではなく、領域を塗り分けるモデルが有効になっています。

**まず試すこと**

serving レジストリで有効になっているモデルが、カウント用ではなくセマンティック用です。カウントの学習ランを**学習モデルを出力 → ONNX (Serving)** で書き出し、その model id を有効化してください。カウント用の書き出しには `model.onnx` と一緒に `instance_inference.json` が入りますが、セマンティック用には入りません。

## ログの確認方法

ログファイルはただのテキストファイルです。メモ帳やテキストエディットで開けます。

API はローテーション付きのログファイルを自分で書き出します。それとは別に、起動スクリプトがコンソールへの出力を保存します。どちらも役に立ちますが、別々のファイルです。

| 種類 | 場所 |
|---|---|
| API のログすべて | リポジトリルートの `logs\app.log`（20MB × 10世代） |
| 警告・エラーのみ | リポジトリルートの `logs\trainer_errors.log`（10MB × 5世代） |
| インストーラー版 Windows での上記2つ | `%LOCALAPPDATA%\Seg-Studio\logs\` |
| コンソール出力（Windows 起動スクリプト） | `logs\windows\trainer_<タイムスタンプ>.log` と `serving_<タイムスタンプ>.log`（起動ごとに1組） |
| コンソール出力（macOS 起動スクリプト） | `logs/macos/trainer.log`、`logs/macos/serving.log` |
| コンソール出力（`scripts/start_local.sh`） | `/tmp/seg_trainer.log`、`/tmp/seg_serving.log` |
| 学習ラン1回分 | `projects/<project_id>/runs/<run_id>/train.log` |

「リポジトリルート」は Seg-Studio のフォルダのことです。

- **JSON 形式のログ**：環境変数 `LOG_FORMAT=json` を設定すると、JSON 形式で出力します。
- **ログレベルの変更**：環境変数 `LOG_LEVEL=DEBUG` を設定すると、デバッグ用の出力も出します。

## 問題を報告する

ここまでの手順で解決しない場合は、[バグ報告テンプレート](../../.github/ISSUE_TEMPLATE/bug_report.md)を使って、<https://github.com/segmen-pixel/seg-studio/issues/new/choose> から issue を作成してください。

**含めていただきたい情報**

- **Seg-Studio のバージョン**：アプリ上部のヘッダーの、アプリ名の横に表示されます。すべての API レスポンスのヘッダー `X-API-Version` でも確認できます。
- **OS とバージョン**：Windows 11 23H2、macOS 14.5 のように書いてください。
- **GPU とドライバー**：`nvidia-smi` の出力を貼るか、「Apple Silicon M2」「CPU のみ」などと書いてください。
- **起動方法**：`start-windows.bat`、`bash start-macos.sh`、`scripts\windows\start_local_windows.bat`、`docker compose up` など、どの方法で起動したかを書いてください。
- **インストール方法**：リリースの ZIP、git clone、Windows インストーラーのどれを使ったかを書いてください。あわせて `python --version` の出力も書いてください。
- **エラーメッセージの全文**：画面の写真ではなく、テキストとしてコピーしてください。
- **ログの末尾50行程度**：まず `trainer_errors.log`、次に `app.log` を貼ってください（場所は[ログの確認方法](#ログの確認方法)を参照）。メモ帳やテキストエディットからコピーするか、次のコマンドを使います。

```bash
# Windows (PowerShell)
Get-Content logs\trainer_errors.log -Tail 50
# macOS / Linux
tail -n 50 logs/trainer_errors.log
```

**含めないでください**

- `.env`、`SEG_API_TOKEN`、`projects/runtime_settings.json` 内の `api_token` の値。これらは認証情報で、issue は公開されます。
- 顧客のデータや、本番の画像・マスク・書き出したモデル。トリミングや黒塗りをするか、公開してよい画像で問題を再現してから貼ってください。
- 顧客や現場を特定できるプロジェクト名・ファイルパス・ホスト名・ユーザー名。貼る前に別の名前に置き換えてください。
- あらゆる種類の個人情報。

ログにはファイルパスやプロジェクト名が含まれます。貼り付ける前に、必ず内容に目を通してください。**セキュリティ上の脆弱性**は、公開の issue ではなく、[SECURITY.md](../../SECURITY.md) の手順に従って報告してください。
