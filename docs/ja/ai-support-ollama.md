# Ollama で AI サポートを使う（Windows と macOS の手順例）

[AI サポート](ai-support.md)を使うと、視覚モデルにプロジェクトのラベル付けを任せられます。このページでは、Seg-Studio だけが入っていてモデルサーバーの無いマシンから始めて、1回の実行が終わるまでを、1つの構成に沿って順に説明します。モデルサーバーに Ollama を使い、Seg-Studio と同じマシンで動かす構成です。これは一例で、ほかのやり方もあります。ほかのモデルサーバー、別のマシンにあるサーバー、MCP ブリッジそのものについては、[AI サポートと MCP ブリッジ](ai-support.md)をご覧ください。

Ollama とモデルは、Seg-Studio とは別のソフトウェアです。Seg-Studio はどちらも同梱していません。どのモデルを使うかは、ご自身で決めてください。ライセンスもそれぞれ別です。Ollama のライセンスと、モデルのライセンス（`ollama show <モデル> --license`）を、ご自分の使い方に照らして確認してください。

## 手順を確認した環境

| | Windows | macOS |
|---|---|---|
| マシン | Windows 11、メモリ 24 GB の NVIDIA GPU | macOS 26、メモリ 64 GB の Apple シリコン |
| Ollama | 0.33.3 | 0.32.14 |
| モデル | `qwen3.8:27b` | `qwen3.8:27b-mlx` |
| モデル（ダウンロードサイズ） | 18 GB | 18 GB |
| モデル（読み込んだ状態でのメモリ、`ollama ps`） | 17 GB（すべて GPU 上） | パネルでの実行中は 21 GB、チャット画面では最大 34 GB |

手順2の確認を通るモデルなら、どれでも同じように使えます。小さいモデルは小さいマシンでも動きますが、同じところまで進めないことがあります。macOS で同じ確認を行ったところ、パラメータ数が約90億のモデルは、プロジェクトの状態を読む操作を繰り返すばかりで、ラベルを1つも付けませんでした。

## 始める前に

- **Seg-Studio をインストールし、起動できる状態にしておきます**（[インストールの詳細](install.md)）。このページのために追加するものはありません。パネルが使う MCP のライブラリは、インストールに含まれています。
- **人がラベルを付けた画像が何枚かあり、まだラベルの付いていない画像も残っているプロジェクトを用意します。** モデルは、ラベルの付いた画像を手本にします。
- **ダウンロードのためにインターネット接続が必要です。** ダウンロードするのは Ollama とモデル、それに macOS では、初めて使うときの SAM のチェックポイントです。ラベル付けそのものは、マシンの中で行われます。Ollama が同じマシンにあり、モデルもそのマシンで動いていれば、画像がそのマシンの外に出ることはありません。Ollama がクラウドのサービスに処理を回すモデル（`cloud` モデル）には、画像が送られます（[データについてモデルに伝えていること](ai-support.md#データについてモデルに伝えていること)を参照）。

## 1. Ollama をインストールする

<https://ollama.com/download> からインストーラーをダウンロードし、Ollama の説明（[Windows](https://docs.ollama.com/windows)、[macOS](https://docs.ollama.com/macos)）に従ってインストールします。インストール後、Ollama はバックグラウンドで動き、`http://127.0.0.1:11434` で応答します。Seg-Studio が Ollama を探しに行くのも、このアドレスです。

新しいターミナル（Windows ではコマンドプロンプトか PowerShell、macOS ではターミナル）で確認します。

```
ollama --version
```

続けて、ブラウザで `http://127.0.0.1:11434` を開きます。`Ollama is running` と表示されます。

## 2. 画像入力とツール呼び出しに対応したモデルを用意する

```
ollama pull qwen3.8:27b
```

Apple シリコンでは、代わりに `ollama pull qwen3.8:27b-mlx` を実行します（確認で使ったのはこちらです）。どちらもダウンロードサイズは 18 GB です。次に、取得したモデルの名前を指定して、そのモデルにできることを確認します（macOS では `ollama show qwen3.8:27b-mlx`）。

```
ollama show qwen3.8:27b
```

```
  Capabilities
    completion
    vision
    tools
    thinking
```

この一覧に `vision` と `tools` の両方が必要です。どちらかが無いモデルでは、ラベル付けができません。ただし、そうしたモデルもパネルの一覧には表示されます。パネルは、Ollama が持っているモデルをすべて並べるためです（`ollama list` でも同じ名前が表示されます）。

## 3. AI サポートパネルを開く

1. Seg-Studio を起動します（`start-windows.bat`、または `bash start-macos.sh`）。
2. **ラベル**画面でプロジェクトを開き、ツール列のいちばん下にある **AI** を押します。
3. パネルの上部に **Ollama** と表示され、その隣の一覧に手順2のモデルが並びます。そのための設定は何もしていません。何も設定していなければ、Seg-Studio は同じマシンの Ollama を探すからです。一覧からモデルを選びます。選んだモデルは Seg-Studio が覚えています。

## 4. 実行する

1. 何をラベル付けするかを、判断の基準も含めて自分の言葉で書き、**実行**を押します。確認では、次の文を使いました。

   > ラベルの付いていない画像に、手本と同じように欠陥（小さな暗い点や傷）のラベルを付けてください。

   パネル上部の表示が**実行中**に変わります。
2. そのプロジェクトで初めての実行では、まず人がラベルを付けた画像でモデルが試し、人がラベルを付けた物体を見つけられる倍率を決めます。この間、マスクは保存されません。決まった倍率はプロジェクトに記録され、次回からの実行ではそのまま使われます。macOS での確認では、SAM のチェックポイントのダウンロードを含めて約4分かかりました。
3. 続いて、このまま進めてよいかをパネルが尋ねます。残りの画像の枚数と、かかる時間の見込みも表示されます（macOS での確認では20枚、約20分）。**…で進める**を押します。20分たっても答えが無いと、何もラベル付けせずに実行が終わります。散らばった小さな点としてラベルを付けるプロジェクトでは、この試しは行われず、ボタンは**進める**だけになります。どちらの場合も、ユーザーガイドに説明があります。
4. ラベルの付いていない画像を1枚ずつ見ていきます。書き込んだマスクは、画像リストに表示されます。何も書き込まなかった画像と、書き込んだマスクに自信の無い画像には、人が確認するための**要確認**の印が付きます。macOS での確認では、20枚に約13分かかり、5枚にマスクを書き込み、残りの15枚に印を付けました。試しの時間を含めた実行全体は約17分で、行ったことのまとめを表示して自動で終了しました。
5. **停止**を押すと、いま行っているステップが終わったところで実行が止まります。モデルが答えている途中なら、その答えが届いたところで止まります（確認では約30秒）。

実行で書き込まれたものは AI の作業として記録され、人が描いたマスクが置き換えられることはありません。パネルの操作については、すべて[ユーザーガイド](user-guide.md#ai-サポートパネル)で説明しています。

## 5. 同じモデルをチャット画面で使う（任意）

`scripts/examples/qwen_mcp_chat.py` は、同じブリッジにつないだ小さなチャット画面です。指示を入力すると、モデルが Seg-Studio のツールを使いながら答え、ツール呼び出しが1つずつ表示されます。これはサンプルであり、製品の一部ではありません。ログインが無く、このマシンの中だけで待ち受けます。また、ブリッジはどのプロジェクトにも書き込めます（[SECURITY.md](../../SECURITY.md#the-example-chat-page)）。

Seg-Studio を起動したまま別のターミナルを開き、Seg-Studio のフォルダに移動します。

Windows:

```
.venv-windows\Scripts\python.exe scripts\examples\qwen_mcp_chat.py --backend ollama --model qwen3.8:27b
```

macOS:

```
.venv-macos/bin/python scripts/examples/qwen_mcp_chat.py --backend ollama --model qwen3.8:27b-mlx
```

指示を送るまで、ターミナルには何も表示されません。`http://127.0.0.1:8765` を開くと、画面の上部にモデルの名前と `ollama · http://127.0.0.1:11434` が表示されます。最初は、読み取るだけの指示を、プロジェクトの名前を添えて出してみます（`my-project` は、ご自分のプロジェクトの名前に置き換えてください）。

> プロジェクト my-project。ラベルの付いていない画像が何枚あるかを数えて教えてください。何も書き込まないでください。

確認では、モデルはツールを1回呼び出したあと、枚数とファイル名を答えました。画面を止めるには、起動したターミナルで `Ctrl+C` を押します。画面とモデルの返事は日本語です。英語にするには `--lang en` を付けます。

## 手順どおりに進まないとき

| 症状 | 対処 |
|---|---|
| パネルのモデル一覧が空 | 問い合わせたアドレスと返ってきた内容が、パネルに表示されます。Seg-Studio を動かしているマシンで、`http://127.0.0.1:11434` に `Ollama is running` と表示されること、`ollama list` にモデルが表示されることを確かめてください。 |
| プロジェクトの状態を読む操作を繰り返すだけで、ラベルを付けない | そのモデルには荷が重い作業です。**停止**を押し、もっと大きいモデルを選んでください。 |
| 最初の答えがなかなか返ってこない | Ollama がモデルを読み込んでいます。`ollama ps` で、読み込まれているモデル、使っているメモリの量、GPU 上にあるかどうか（`100% GPU`）が分かります。 |
| Ollama が別のマシンにある | パネルではなく、Seg-Studio を動かしているマシン側で設定します（[AI サポートと MCP ブリッジの「A. AI サポートパネルを使う」](ai-support.md#a-ai-サポートパネルを使う)を参照）。 |

Ollama 自身のチャット画面と `ollama run` は、モデルと直接やりとりするためのものです。Seg-Studio のツールは、そこにはつながっていません（Ollama 0.33.3 で確認）。モデルにプロジェクトの作業をさせるには、パネル、上で紹介したチャット画面、手持ちの MCP クライアント（[AI サポートと MCP ブリッジの「B. 手持ちの MCP クライアントから使う」](ai-support.md#b-手持ちの-mcp-クライアントから使う)を参照）のいずれかを使います。
