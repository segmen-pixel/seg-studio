## Phase 1：開発者に届ける（v1.1）

**目標**：ML 開発者や研究者がすぐに試せる状態にします。

**期間の目安**：1〜2か月

### パッケージ配布
- [x] `pyproject.toml` の作成（hatchling でビルド）
- [ ] `pip install seg-studio` による API と CLI のインストール
- [ ] エントリポイント：`seg-studio start` でサーバーを起動
- [ ] PyPI への公開（TestPyPI → 本番）
- [ ] GitHub Actions と Trusted Publisher による自動公開

### Windows ポータブルパッケージ

Phase 3 から前倒ししました。ランタイムの同梱はすでに実現しており、残っているのは実装作業ではありません。

- [x] 自己完結型のビルド。Python 3.11 と CUDA 版 PyTorch を同梱しているため、Python、git、CUDA Toolkit を事前にインストールする必要がありません（`scripts/build_installer.py --platform win64 --lean`）。
- [ ] 同梱 DLL を再配布してよいかの整理。これが片付くまで、バイナリでの配布はできません（ソースでの配布には影響しません）。
  - NVIDIA：`cusolverMg64_11.dll` と `nvperf_host.dll` が、CUDA EULA の再配布可能なファイルの一覧に載っていません。
  - libvips：`pyvips-binary` のバージョンを pin していないため、同梱した LGPL バイナリに対応するソースのバージョンを特定できません。
  - FFmpeg：OpenCV の DLL に静的リンクされています。そのため LGPL-2.1 第6条により、ソースの提示だけでなく、再リンクできる形での提供が求められます。
- [ ] 置き場所の確保。パッケージは約 3 GB ですが、GitHub Release に添付できるのは1ファイルあたり 2 GiB 未満です。

### モデル・重みの配布
- [x] Hugging Face Hub のモデルリポジトリ（`segmen-pixel/seg-studio`、SAM のチェックポイントの配信で稼働中）
- [ ] 初回起動時に教師モデルを自動でダウンロードする機能
- [ ] `.gitignore` に `*.pth`、`*.onnx`、`*.mlmodel` が入っていることの確認
- [ ] ダウンロードの進捗表示（CLI と UI の両方）

### 開発者体験
- [ ] `seg-studio --demo` でデモデータ付きですぐに起動
- [ ] API ドキュメント（Swagger）の充実
- [x] Contributing ガイドの整備（`CONTRIBUTING.md`）
- [x] GitHub Issue / PR テンプレートの整備（`.github/ISSUE_TEMPLATE/`、`.github/PULL_REQUEST_TEMPLATE.md`）

## Phase 3：非エンジニアに届ける（v2.0）

**目標**：ターミナルを一度も開かずに使える体験を作ります。農家や医療従事者、工場の作業者が、自分の力で使えるようにします。

**期間の目安**：3〜6か月

### デスクトップアプリ化

Python ランタイムの同梱は Phase 1 に移しました（Windows 版のパッケージは、すでに専用のインタプリタを同梱しています）。ここに残っているのは、それを包む外側の部分です。

- [ ] フォルダを展開する形ではない、本来のインストーラ
  - Windows：`.exe` のインストーラ（NSIS または WiX）を用意します。
  - macOS：`.dmg` を用意します。署名と公証があってはじめて配る意味があり、無ければ利用者全員が Gatekeeper を手動で解除することになります。
- [ ] GPU セットアップウィザード
  - CUDA を使えるかどうかの自動判定
  - CPU モードへのフォールバックと、性能上の制約の明示
- [ ] 自動アップデートの仕組み

### UX の改善（非エンジニア向け）
- [ ] オンボーディングウィザード
  - 「何を検出したいですか？」と聞いて、テンプレートを提案
  - サンプルプロジェクトで操作を体験
- [ ] 学習パラメータの自動推奨（現在の auto-tune をさらに簡単に）
  - 「画像をアップロード → 学習ボタン → 完了」の3ステップ
  - 詳細設定は「上級者向け」に分けて非表示
- [ ] 日本語と英語以外の言語への対応（i18n）
- [ ] 学習完了の通知（メールまたはブラウザ通知）

## Phase 4：エコシステムの拡大（v2.x〜）

**目標**：セグメンテーション以外にも対応を広げます。業界に特化したテンプレートも用意します。

**期間の目安**：6か月〜

### タスク拡張
- [ ] 物体検出（Object Detection）を独立したタスクとして提供します。検出そのものは、個数カウント（インスタンスセグメンテーション）としてすでに提供しています。そのため、ゼロから作るのではなく、直接使える形にする作業になります。
- [ ] 分類（Classification）に対応します。

### 業界テンプレート
- [ ] 農業パック：病害の検出、雑草の検出、収穫適期の判定
- [ ] 製造パック：外観検査、欠陥の分類、寸法の計測
- [ ] 医療パック：細胞のセグメンテーション、病理画像の解析
- [ ] パックごとの事前学習済みモデル、サンプルデータ、チュートリアル

### 連携・統合
- [ ] iPad / iPhone アプリとの連携強化（CoreML での直接デプロイ）
- [ ] エッジデバイスへの対応（Jetson、Raspberry Pi）
- [x] REST API / Python SDK によるプログラムからの連携（`/v2` のストリーミング推論 API と `packages/seg-sdk`）

## 判断基準：各 Phase で何を優先するか

| 判断軸 | 優先度 |
|--------|--------|
| **ユーザーが30秒で価値を感じるか** | 最優先 |
| **インストールの障壁を下げるか** | 最優先 |
| **既存コードの変更が最小か** | 高 |
| **一人でも実現できるか** | 高 |
| **新しい技術スタックが不要か** | 中 |
